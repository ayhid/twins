## Phase Goal

ROADMAP goal (verbatim): The scan pipeline runs inside `twins-core`, and any caller (CLI now, app and agent later) can follow its progress by stage and cancel it, on the Rust 1.90 toolchain Tauri needs. (Not in user-story form. The planner did not invent one; see plan 01-01.)

Gap closed: **G-01-1** (minor, UAT test 1). Truth to restore: "The text scan report is easy to read: groups are visually separated, the keep/remove roles are clear and paths are not needlessly repeated."

<objective>
Make the `twins scan` text report readable without touching the JSON report. Today `report::write_text` prints groups back to back. Every row repeats the full absolute path, an unexplained star marks the kept file, and removal rows carry no marker at all. Hardlinks of the kept file, which are never removed, also get that blank marker, so they look exactly like removals.

The new layout labels every row (`keep`, `keep … (hardlink)`, `remove`), prints each group's shared folder once with rows relative to it, and separates groups with one blank line. It stays plain text: no color and no new dependency.

Purpose: UAT gap G-01-1 (CORE-01: the CLI caller renders the core pipeline's result). Success criterion 1 still holds: same groups, same JSON schema v1. Only the human text layout changes, as the user asked in UAT. Labelled roles also serve the Core Value: the human view of the plan must state plainly which file survives.
Output: a new `write_text` body with private helpers in report.rs, plus updated and new exact-format tests in core and CLI.

Path shortening uses each group's shared folder rather than the scanned root (Claude's discretion within the gap's "relative to the scanned root or ~"). `Report.roots` keeps roots as the caller spelled them, for example `.`, while member paths are absolute, so a root-prefix match would need cwd or canonicalization inside a pure renderer. The shared folder is computed from the report alone, is never longer than the root-relative path, and needs no environment lookup for `~`.
</objective>

GroupEntry fields used: `size`, `reclaimable_bytes`, `keep: String` (path of the kept file), `remove: Vec<String>` (paths to remove), `files: Vec<FileEntry>` (every member, sorted by path, each with `path: String`). Helpers already in the file: `human_size`, `plural`.

Role semantics (crates/twins-core/src/group/keep.rs, Keeper::choose): remove holds every member whose (device, inode) differs from the kept file's. So a member that is neither `keep` nor in `remove` is exactly a hardlink of the kept file, and it is never removed.

Target layout, the contract both tasks test against exactly:
- Group header, line 1, UNCHANGED: `[{n}] {human_size(size)} × {member count}  ({human_size(reclaimable_bytes)} reclaimable)`.
- Folder line, only when the members' parent folders share more than the filesystem root: two spaces, the shared folder, then `/`. Example: `  /r/`.
- One row per member: four spaces, the label left-aligned in a 6-column field, two spaces, then the path. The path is relative to the shared folder when a folder line is printed, and the full path otherwise. Labels: `keep` for the member equal to `keep`; `keep` plus the suffix `  (hardlink)` for a member that is neither `keep` nor in `remove`; `remove` for a member in `remove`. So the rows read `    keep    a.bin`, `    keep    c.bin  (hardlink)` and `    remove  b.bin`.
- Row order: the kept file, then its hardlinks, then removals. Within a role, keep the report's path order (a stable sort by role rank on `files`).
- Exactly one blank line between groups. The totals line keeps its exact current text and its single blank line before it.
- The empty report stays `No duplicates found ({n} files scanned).` unchanged.
- Control characters in a displayed path, on folder lines and rows: every char for which char::is_control is true is replaced by its char::escape_debug form, so a newline shows as backslash followed by n. Every other char is printed unchanged, including non-ASCII.
